# 理稿台（ligaotai）

把几百万字、乱成一团的长篇手稿，**理清 → 取舍 → 补写**成一本书的本地工作台。

> 🚧 开发中。后端已经能把一堆乱稿一路理到全书地图（导入 / 切场景 / 查重 / 场景卡 / 实体合并 / 归线排序 / 档案·矛盾·地图）。还没有界面。

## 要解决什么

手稿写了很多年，散在几百个文件里：有章节、有片段、有设定笔记，文件名乱、顺序乱；同一个场景写过好几版；人名前后不统一；还有好几条没写完的支线。任何 AI 的上下文都装不下全书，所以没法直接让 AI 帮忙成书。

市面上的写作工具（NovelWriter 等）都假设手上是「一本章节有序的书」，缺少「理乱稿」这一层。理稿台补的就是这一层。

## 思路：分层压缩

AI 一次读不完全书，就把全书压成四层，每层都能装进一次对话：

| 层 | 内容 |
|---|---|
| L0 原文 | 切成场景块，每块有固定编号，永不修改 |
| L1 场景卡 | 每块一张结构化卡片（摘要、人物、地点、时间线索、设定事实…） |
| L2 档案 | 每条支线一份档案、每个世界一份设定集 |
| L3 全书地图 | 全书总览，约 2 万字 |

铁律：**AI 产出的东西一律先当草稿，作者确认后才算数。**

完整设计见 [`docs/superpowers/specs/2026-09-10-ligaotai-design.md`](docs/superpowers/specs/2026-09-10-ligaotai-design.md)，界面原型见 [`docs/prototype/ligaotai-prototype.html`](docs/prototype/ligaotai-prototype.html)（下载后用浏览器打开）。

### 已经能做的

- **导入**：递归导入文件夹里的 `.txt` / `.md` / `.docx`，自动识别 UTF-8 / GBK 编码；重复导入只处理改动过的文件。
- **切场景**：按章节标题（`第X章/回/卷`、`Chapter N`、Markdown `#`）、分隔符（`***`、`◇◇◇`）、连续空行切块，太长的块在 5000 字以内就近切开。兼容网文常见的标题写法（`第105章 什么？！`），不会把大纲行、随手备注当成章节。
- **查重**：找出同一场景写过的不同版本（整章重写、摘出来的片段），自动选主版本，作者可以改。
- **编号稳定**：场景编号一旦分配永不重排；原稿改动后，受影响的场景会被标成「过期」。
- **场景卡**（步骤 4）：每个场景块调一次批量档模型，出结构化卡片（摘要、人物、地点、组织、事实……）；人名 / 地名 / 组织名和事实原文都会核对能不能在原文里找到，找不到就带着问题重试，还是不行就丢掉并记在卡上，卡照样保存。
- **实体合并**（步骤 5）：把全书同一人物 / 地点 / 组织的不同叫法交给综合档模型归组，作者确认、改名、合并、拆分；确认过的组重跑时原样保留。
- **归线排序**（步骤 6）：只看场景卡不读原文，分五步跑完——划世界（同一个故事世界的块归一起）、划支线（分出主线和各条支线）、线内排序（给每条线里的块排先后，顺带估故事时间和把握度）、跨线对齐（支线挂到主线的时间轴上，标出交汇点）、找缺口（从卡里提到、但全书没写的事）。作者可以改线和世界：改名、合并、拆分、挪块、设主线、确认（确认过的线重跑时原样保留）。
- **档案 / 矛盾 / 全书地图**（步骤 7）：拿场景卡和归线结果，一次跑出四件东西——每条支线一份档案、每个故事世界一份设定集、一份全书矛盾清单、一份全书地图。
  - 档案和设定集里**每句结论都要带场景编号**，编号必须真实存在、且属于这份档案的范围，不合规就带着问题重试。
  - 矛盾扫描走「程序分组 → 按批判断」：先用实体表把同一个人的不同叫法归一，按 (主语, 属性) 分组，**只把值对不上的组送给模型**判是真矛盾、合理变化还是拿不准。宁可多报——模型拿不准时给「无法判断」而不是「合理变化」。
  - 设定集里的「（多个说法）」会自动回填成对应的矛盾编号。
  - 按签名跳过：原稿和上游结果没变的档案不会重跑，也就不会重复花钱；上游变了的会标成「过期」，文件留着给作者看。
- 所有数据都是书文件夹里的 md / json，普通文本编辑器就能打开。
- **取舍**（二期）：裁决矛盾写进定稿设定；看板四列定去留，AI 给建议、拖进砍掉 / 合并时列出会断掉的交汇点、独有人物、伏笔；程序按故事时间排出骨架、模型分卷分章并给每个空洞写补写说明，骨架可以手改；按骨架导出 md / txt。

### 验收

- **查重**：把公版《西游记》（约 76 万字）拆成 174 个乱命名、混着 GBK 和 docx 的文件，删章、截断、加别名、植入 15 个重写版，再让理稿台去理：**15 个重写版全部找到，没有误合并，全程约 7 秒。**详见 [`docs/验收记录/2026-09-11-计划1-查重.md`](docs/验收记录/2026-09-11-计划1-查重.md)。
- **实体合并**：同一份乱稿（268 个场景）里植入 3 个人物别名，交给理稿台跑场景卡 + 实体合并：**3 / 3 全部被合并，没有误合并。**详见 [`docs/验收记录/2026-09-12-计划2a-实体合并.md`](docs/验收记录/2026-09-12-计划2a-实体合并.md)。
- **归线排序**：判据是「理出来的顺序和原书顺序的 Kendall τ ≥ 0.8」。除了《西游记》，另外拿一本模型确认不熟悉的冷门公版小说（《雪月梅传》，50 回 26 万字，同样打乱成 84 个文件）验收，避免模型靠背书拿高分：**《西游记》τ = 1.0，《雪月梅传》τ = 0.93，两本都没有未分配的块，也没有排序失败的线。**详见 [`docs/验收记录/2026-09-16-计划2b-归线.md`](docs/验收记录/2026-09-16-计划2b-归线.md)。
- **档案 / 矛盾 / 全书地图**：三条判据——引用编造率 ≤ 2%、没带编号的结论句 ≤ 10%、植入矛盾召回 ≥ 8/10。在《雪月梅传》乱稿里额外植入 10 处人造矛盾（同一个人物在两个不同章节被写成两个不同的年龄），跑完步骤 1–7 再核：**2324 条引用里 0 条编造（0.0%），1504 条结论句里 109 条没带编号（7.25%），植入矛盾召回 8/10，三条全过。**
  两处没召回的都不在矛盾扫描本身：一处是另一端的陈述没被抽成事实，一处是模型判成「合理变化」——而那个判断是对的（书里时间跨度好几年，人物从十六岁长到二十四岁本来就正常），是验收样本造得不够狠。
  ⚠️ 这是个**下限测试**：人造矛盾写得很直白，能说明基本能力在，不能用来说明在真实稿件上的表现。详见 [`docs/验收记录/2026-09-21-计划2c-档案矛盾地图.md`](docs/验收记录/2026-09-21-计划2c-档案矛盾地图.md)。
- **界面**：两本验收书（《西游记》《雪月梅传》）九个页面浅色、深色各过一遍，窄窗口过重点页，交互态（点线、点缺口、选场景、开档案）截图核对。截图抓到 9 个单元测试抓不到的画面 / 行为问题，已全部修掉；没验到的情形和留下的问题如实写在 [`docs/验收记录/2026-09-22-计划3-界面.md`](docs/验收记录/2026-09-22-计划3-界面.md)。

## 跑起来

需要 Python 3.11+ 和 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync                      # 安装依赖
uv run pytest -q             # 跑测试
uv run python -m ligaotai    # 启动后端：http://127.0.0.1:8765/docs 可以看到全部接口
```

服务只监听本机 `127.0.0.1`，不对外网开放。

### 界面

后端自带网页界面。构建时需要 Node，**日常使用不需要**。

首次构建：

```bash
cd web
npm install
npm run build
```

然后照常启动后端，浏览器打开 http://127.0.0.1:8765/ 。

开发时前后端分开跑（前端改动热更新）：

```bash
uv run python -m ligaotai          # 一个终端
cd web && npm run dev              # 另一个终端，开 http://localhost:5173
```

界面能做什么：

- **书架**：建书、选文件夹导入。
- **理稿流水线**：7 步各自的进度、失败项、重跑。要作者拍板的两步做成流水线下的子页（实体确认没有待确认项时导航里收起；归线确认常驻，因为改名、设主线平时也要用）：
  - **实体确认**：第 5 步的合并建议，逐组接受或拆开；跨批冲突可以手动合并。
  - **归线确认**：第 6 步拿不准的块接受或拒绝，未分配的块归到某条线；线可以改名、设为主线。（合并、拆分线目前只有接口，界面还没做。）
- **全景**：世界 × 支线的泳道图，横轴是故事时间（跨度太大的空白自动断开），标出缺口、交汇点、多版本；定不了时间的场景和缺口挂在线尾，不会丢。点一条线看它的状态、概述和写到哪，点缺口簇看缺了哪些事。
- **场景浏览**：原文和场景卡左右对照；按编号 / 标题 / 卡片摘要搜索，可以勾上「也搜原文」；查重找到的版本组可以改主版本。
- **设定库**：每条支线的档案、每个世界的设定集、全书地图；档案是旧模型写的会提示。
- **矛盾**：全书矛盾清单，默认只展开严重的；裁决：以某个值为准 / 自己写 / 先放着。
- **取舍看板**（二期）：四列（保留 / 合并 / 砍掉 / 还没想好）拖动定去留；AI 给建议；拖进砍掉 / 合并会拉一次影响检查，列出会断掉的交汇点、独有人物、可能相关的伏笔。
- **成书骨架**（二期）：程序按故事时间排出的卷章结构，模型起名、写每个空洞的补写说明；可以手改，改动会标出场景已被砍 / 已换主版本 / 从骨架里消失；一键导出 md / txt。
- **设置**：接口地址、模型、key、并发数、书库目录，带「测试连接」。

界面**不显示任何费用数字，也不做事前估价**——估价在本项目里反复失准。实际用量照旧记在 `book.json` 里。

### 配置模型

场景卡、实体合并、归线、档案要接一个 OpenAI 兼容的模型接口，默认配置指向 DeepSeek（`deepseek-flash`，批量档抽卡不开思考、综合档合并实体开思考）。配 key 二选一：

- 仓库根目录建一个 `config.json`（已在 `.gitignore` 里，不会被提交）：`{"api_key": "sk-xxxx"}`；
- 或设环境变量 `LIGAOTAI_API_KEY=sk-xxxx`（`config.json` 里配了就优先用 `config.json`）。

配完用 `POST /api/config/test`（或 `/docs` 页面里点一下）测连通性，两档模型各返回一次成败。

### 提示词

发给模型的提示词都在 `prompts/` 下，是纯 Markdown，可以直接改（改完相关结果会判过期、重跑）：

| 文件 | 用在哪一步 |
|---|---|
| `cards.md` | 步骤 4 抽场景卡 |
| `entities.md` | 步骤 5 实体合并 |
| `threads_worlds.md` / `threads_lines.md` / `threads_order.md` / `threads_align.md` / `threads_gaps.md` | 步骤 6 归线的五个小步 |
| `archive_thread.md` / `archive_world.md` / `contradictions.md` / `map.md` | 步骤 7 的支线档案 / 世界设定集 / 矛盾扫描 / 全书地图 |

⚠️ 改提示词会让**所有**相关结果的缓存失效。步骤 4 的 `cards.md` 尤其贵——改一个字，全书每个场景都要重抽一次卡。

**费用提示**：验收时同一份乱稿、268 个场景，跑一遍场景卡 + 实体合并总共约 470 次调用、花费约 **1.6 美元**（按 DeepSeek 高峰价估算，实际以账单为准；DeepSeek 闲时价格是高峰的一半）。

自己跑一遍西游记验收：

```bash
mkdir -p data
curl -L -o data/xiyouji-pg23962.txt https://www.gutenberg.org/cache/epub/23962/pg23962.txt
uv run python tools/scramble.py --src data/xiyouji-pg23962.txt --out data/乱稿-西游记 --seed 7
uv run python tools/eval_dedup.py --folder data/乱稿-西游记 --key data/乱稿-西游记-答案.json
```

`tools/` 下每一步都有对应的验收脚本，都能单独跑：

| 脚本 | 验什么 |
|---|---|
| `eval_dedup.py` | 查重（步骤 1–3，不花钱） |
| `eval_entities.py` | 实体合并（步骤 5） |
| `eval_threads.py` | 归线排序（步骤 6），顺带把步骤 1–6 跑完 |
| `eval_archives.py` | 档案 / 矛盾 / 地图（步骤 7） |
| `probe_book.py` | 探模型熟不熟这本书——太熟的书验收分数会偏乐观 |

验收步骤 7：

```bash
# 造乱稿时额外植入 10 处人造矛盾（--characters 给一份人物名单，每人写 canonical 和 names）
uv run python tools/scramble.py --src data/pg26739.txt --out data/乱稿-雪月梅     --aliases data/别名-雪月梅.json --characters data/人物-雪月梅.json --contradictions 10

# 跑完步骤 1–6（会真调模型）
uv run python tools/eval_threads.py --folder data/乱稿-雪月梅 --key data/乱稿-雪月梅-答案.json

# 步骤 7 跑完之后核三条判据。--folder 要的是乱稿**文件夹名**，不是路径
uv run python tools/eval_archives.py --book <书库>/<书名>     --key data/乱稿-雪月梅-答案.json --folder 乱稿-雪月梅 --report data/验收-档案.json

# 抽 10 条带编号的结论句出来人工看
uv run python tools/eval_archives.py --book <书库>/<书名> --sample 10 --out data/抽查.md
```

每个要花钱的脚本都带 `--estimate`，先估一遍再决定跑不跑。
