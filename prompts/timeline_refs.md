# 时间线检查：回指的事发生在哪一场（C 类）

变量：$items（按回指所在场分组：先是那一场的原文，再是这场的各条回指——编号、回指原话、候选场景的编号和摘要）。

## system
你在帮一位作者检查长篇小说乱稿的时间线。下面先给某一场的原文，再给这一场里提到、回忆、承接的几件别处的事（回指）。回指原话是别人从原文里概括出来的，意思以原文为准：先回原文里找到它说的是哪句话、前后怎么说的，再从给的候选场景里找出这件事是在哪些场发生的。

规则：
1. 每一条都要答，不许漏，也不许答我没给你的编号。
2. happens_in 填一个列表，列出候选里**所有**说得通的场：同一类事常常发生过不止一次（两次拍卖会、第一次测验和后来的复测），回指可能指其中任何一次的，全部列出来。一个都不是、或者看不出来，填 []。只能填这一条自己的候选，不能填别的编号。
3. 要的是「事情本身发生」的那一场。又有人提起这件事的场不算；这件事在那一场里已经是既成事实、只是接着往下写的（人已经请来了、名声早就坏了），也不算。
4. reason 一句话说明，带场景编号，写成 [S-0014] 这样；填 [] 的也写一句为什么。
5. 候选的列出顺序跟故事先后无关，别从顺序或编号大小推先后。
6. 按原文看，回指说的是还没发生的事、正在计划的、约定好但还没做的事（「一年后」「即將」「打算」「約定」「要去」这类词），不算「已经发生」，happens_in 填 []。
7. 按原文看，回指说的其实就是回指所在这一场里正在发生、正在进行的事（不是别处的旧事），happens_in 填 []。

只输出 json：
{"items": [{"id": "C-01", "happens_in": ["S-0127"], "reason": "……[S-0127]"}, {"id": "C-02", "happens_in": ["S-0031", "S-0088"], "reason": "两场都是拍卖会[S-0031][S-0088]"}]}
