## 4. 全景页

全景页是本计划最难的一块，也是原型与真数据出入最大的一块。以下规格按仓库里真实的归线结果（`data/验收书库/验收-实体-乱稿-{西游记,雪月梅-c}-s7/世界与支线.json`）定。

### 4.1 为什么不能照原型直接画

原型用虚构数据，七条线都落在 1–11 年内。真数据不是这样：

| | 雪月梅 | 西游记 |
|---|---|---|
| 世界 / 支线 | 1 / 5 | 1 / 3 |
| 全局时间跨度 | -10.0 ~ 6.6（16.6） | **-871.8 ~ 14.0（885.8）** |
| 主线占全宽 | 40% | **1.6%** |

西游记三条线的 `offset` 分别是 0 / -871.8 / -19。等比例渲染时主线 210 个场景挤进 1.6% 的宽度（1440px 屏上约 23 像素），中间 -500 到 -19 是 481 年纯空白、白占 54% 的画布。

### 4.2 断轴（决定了横轴）

把一个场景都没有的长空白压掉：

1. 取全书所有场景的全局时间点 `P = { thread.offset + times[sid].t }`（`t` 为 null 的场景不参与），得全局 `[lo, hi]`。
2. `P` 排序去重，算相邻间隙。间隙 > `(hi-lo) * BREAK_RATIO`（默认 **0.05**）的判为断口。
3. 断口把数轴切成若干**有效区块**。宽度这样分：
   - 先扣掉 `n_breaks × BREAK_WIDTH`（`BREAK_WIDTH` 默认 **3%**），断口画斜纹并标出「这里跨了 N 年」。
   - 再给每个区块保底 `MIN_BLOCK`（默认 **1%**）——跨度为 0 的单点区块只拿保底。
   - 剩余宽度按各区块的时间跨度**按比例**分配。
   - 保底和断口加起来超过 100% 时（区块特别碎），`BREAK_WIDTH` 按比例缩小到能放下为止，最小不低于 1%；仍放不下就不断轴，退回等比例轴并在图上说明。
4. 映射函数 `x(t)`：定位 `t` 所在区块，块内线性插值。落在断口内的 `t` 不该出现（断口按定义内部无点），防御性地吸附到最近的区块边界。

西游记实测：885.8 年压成三个有效区块（1 点 + 12.1 年 + 33 年），主线从 1.6% 变成 **28%**，一个场景都没丢。

**边界**：全部时间点相同 → 单区块居中；一个时间点都没有 → 不渲染图，出空态提示「步骤 6 还没跑或没估出时间」。

### 4.3 段（原型的 `segs` 在真数据里不存在）

真数据每个场景存一个时间点（`times[sid].t`），没有「段」。段这样生成：

- 一条线的场景按全局时间排序（`t` 为 null 的排除）。
- **落在同一个有效区块内的连续场景合成一段** `[最早, 最晚]`；跨区块自然断开。
- 一段只有一个点时给 `MIN_BLOCK` 的最小宽度。

`outlines` 字段在两本真书里**全是空的**，所以原型图例里「只有提纲碎片」这种条带**一期不画、图例里也不出现**——不画一个永远为空的图例。等真有数据再加。

### 4.4 缺口

缺口（`gaps`）是本页第二个坑。真数据：雪月梅 81 个（单条线最多 36 个），西游记 42 个。

**原型「每个缺口画一段虚线区间」的做法在真数据上不成立**：

| | 雪月梅 | 西游记 |
|---|---|---|
| `after` + `before` 都有（画得出区间） | 33 | 39 |
| **只有 `before`**（起点未知） | **41** | 2 |
| 只有 `after` | 1 | 1 |
| 两端都没有 | 6 | 0 |
| 区间窄于全轴 0.5% | 7 | **30（77%）** |

L-005 一条线 36 个缺口里只有 7 个画得出区间；西游记算得出区间的有 77% 窄到 3 像素。

**改成标记点 + 两层聚合**：

1. **定位**：有 `before` 且该场景有 `t` → 用 `before` 的全局时间；否则退到 `after`；两者都取不到 → **orphan**。
2. **第一层**：定位值完全相同的合并。
3. **第二层**：按 `x(anchor)` 排序，相邻簇的 **`x` 距离** < `CLUSTER_RATIO`（默认轴宽 **1.5%**）的合并，**迭代到稳定**（合并后可能又跟下一簇靠近）。合并簇的位置取成员 **`x` 值的中点**（不是时间值的中点——聚合是为了避免像素重叠，判据和结果都在 `x` 空间）。
   - 第二层的结果**随容器宽度变化**：轴变窄时更多簇会合并。所以聚合在渲染层算、resize 时重算，不缓存在 store 里。
4. 单个缺口画三角标；簇画三角标 + 数量角标。点击出右侧详情，列出该簇每个缺口的 `event` 原文与 `mentioned_in`。
5. **orphan 挂在线尾的小标签**（「N 处定不了位」），点开单独列出。**不静默丢掉。**

只做第一层是不够的：L-005 的 63.25 / 64.46 / 65.06 / 66.27 四个位置的角标会叠在一起、数字都看不清。两层聚合后 31 个能定位的缺口收成 9 个落点。

### 4.5 其它标记

- **断 / 完 / 待定**：取 `thread.end.state`（真值是 `完结` / `待定`），画在该线最后一段的末端。**别拿 `status` 判完没完**——它说的是另一回事：`threads.py` 里 `status = CONFIRMED if t.locked else DRAFT`，表示作者确认过这条线的划分没有（`draft` / `confirmed`），跟故事写完没有正交。
- **交汇点**：`intersections` 的 `(thread, scene, main_scene)`，在支线 `scene` 的位置画圆圈，悬停出 `reason`。
- **多版本**：从 `GET /versions` 取，在对应场景位置标「N 版」。
- **`t` 为 null 的场景**：**不插值**（插值等于编造位置），跟 orphan 缺口一样汇总到线尾标签。
- **`order_failed` 为真的线**：整条线加醒目底色 + 一句「这条线排序失败，顺序不可信」。

### 4.6 右侧详情面板

选中一条线时显示：线名、世界、状态、场景数、`about`、`end.note`（写到哪）、该线的缺口清单、`order_failed` 提示。选中缺口簇时显示该簇的缺口清单。

## 5. 各页面要点

- **书架 / 导入**：建书、选文件夹导入。**必须显示并记录来源文件夹的完整路径**，与该书已记录的来源路径不同时提醒（待办：两个不同位置的同名文件夹会互相覆盖）。
- **流水线**：七步进度（`done`/`total`/`message`）、失败项、单步重跑。不显示费用，不显示调用次数（第 7.3 节）。第 3 步查重结果里要提示「作废的手选」；查重任务运行中禁用「设为主版本」。
- **实体确认**：`GET /entities` 的合并建议逐组确认；**`conflicts` 必须单独列出给作者手动处理**（待办：跨批冲突组的非锚点名会成 single，觀世音、紅孩兒实测漏合）。
- **归线确认**：`pending`（模型建议归入已确认线的块）一键接受 / 拒绝；`unassigned` 能拖进线；`order_failed` 的线醒目提示。
- **场景浏览**：原文 + 场景卡并列；版本组并排对比；全文搜索（原文和卡片）。
- **设定库**：支线档案、世界设定集、全书地图。**每份档案对比 `index[...].model` 与当前 `synth.model`，不一致时提示「这份是 X 模型写的，当前配置是 Y，要重跑吗」**（作者 9-20 拍板：换模型不进签名，用提示代替）。`outdated` 的档案要明确标出。
- **矛盾**：一期只展示不裁决。默认只展开「严重」，「无法判断」和「合理变化」折叠。
- **设置**：接口地址、模型名、key、并发数、书库目录，带「测试连接」（`POST /api/config/test`）。**单价字段一并去掉**（第 7.3 节）。

## 6. 数据流

- **所有写操作完成后重新拉取相关资源，不做乐观更新。** 后端是文件落盘、带过期与对账逻辑，前端猜状态必然跟真实文件对不上。
- **全局 job store**：轮询 `GET /api/jobs/current`，间隔 1 秒；任务结束后自动刷新当前页数据。不加 SSE——后端 `Job` 已有 `status/done/total/message/error`，轮询够用且不用改后端协议。
- **一次只跑一个任务**是后端硬约束（`JobRunner.submit` 撞上会抛 `BusyError`）。前端据此在有任务运行时统一禁用所有会触发任务、以及会跟运行中任务打架的按钮。待办里「查重运行时点『设为主版本』有极小概率被覆盖」靠这条统一堵掉，不在每个页面各写一遍。

## 7. 三个明确的取舍

### 7.1 泳道图自己写，不引图表库

调研过 `laurens94/vue-timeline-chart` 和 `vasturiano/timelines-chart`，都不用。两者都假设横轴是真实时间戳，而这里是无量纲的估算故事时间，用库要先造假日期再改轴标签；断/完/交汇/多版本/缺口五种标记全是本项目特有的，库都得自定义渲染；断轴更是库不提供的。原型已用纯 CSS 绝对定位 + 一个 `x(年)→百分比` 函数画通，核心 20 行，搬成 Vue 组件即可。真数据 1 个世界 3–6 条线，纯 DOM 没有性能问题，不需要虚拟滚动。

### 7.2 视觉照原型

原型的 `:root` 本来就是纸色底，深色是 `prefers-color-scheme: dark` 的自动跟随，与总 spec 第 8 章那句「冷调纸色底、宋体标题、朱红只用于断点/缺口/严重矛盾，支持深色模式」一致。直接搬变量表。

### 7.3 界面不显示费用，也不做费用估算

**作者 2026-09-21 拍板**：事前估价一律不做，累计实花与调用次数也都不显示。

理由是估价在本项目里反复失准且偏差没规律：②b 归线估 $1.32 实花 $1.57；②c Task 24 计划里写的「约 $0.3」真实是 $2.77～$4.15（提示词一改，缓存键全变，全部重付），而那个 $0.3 是 `eval_threads.py --estimate` 的 `cards_needed=0` 口径算出来的。

**这改了总 spec 第 9 章**那句「从接口返回的 usage 统计 token，乘以设置里的单价，估算累计费用，显示在流水线页」，以及第 8 章流水线页描述里的「累计费用估算」。

**只改界面，不动后端**：`AppConfig.price_input` / `price_output` 保留（`llm.Usage.cost()` 和 `tools/eval_threads.py`、`tools/eval_archives.py` 都在用，删了会崩）；各步骤照旧往 `book.json` 写 usage 记录、summary 里照旧带 `cost_usd`。界面的做法是：设置页**不渲染**这两个字段，流水线页**不渲染** `cost_usd`，`usage` 相关的数字一个都不往页面上放。

## 8. 后端一并修掉的

这几条写在 `已知问题与待办.md` 的「计划③（界面）要处理的」里，但改的是 `api.py` / `book.py` 而不是界面：

- `GET /scenes`：某个场景文件被改坏时只返回 500，没告诉界面是哪个文件。
- 卡文件结构被手改坏（`dropped` 里有 null、`card` 是字符串）→ 卡片列表接口整体 500；`实体.json` 不是合法 JSON → `GET /entities` 500、confirm 400 且 detail 是原始 `JSONDecodeError`；实体条目缺字段的 `KeyError` 被报成 404。
- `safe_name("..")` / `"."` / `"   "` 抛 `ValueError`，`archive_body` 等接口没接，返回 500 而不是 404。
- 场景卡暂停后单卡重做，`summary` 会盖掉「已暂停」：`only` 模式下若传入前状态不是 done，保留旧的 `summary`/`error`，不要用单卡这次的统计覆盖。

共同点：程序自己写的文件不会长这样，只影响手改和外来文件；界面要拿到具体错误信息而不是裸 500。

## 9. 测试

- **算得出对错的一律单元测试**：断轴成轴（含全部点相同、无点、单点区块、间隙恰好等于阈值）、缺口两层聚合（含迭代收敛、orphan 分流）、段生成（含跨区块断开、`t` 为 null 排除）、job 状态机。
- **`LaneChart` 组件测**：给定一份真实形态的数据，断言标记数量与落点位置。
  - **测试数据从 `data/验收书库/验收-实体-乱稿-{西游记,雪月梅-c}-s7/世界与支线.json` 提取，固化成 `web/src/components/__fixtures__/` 下的样本提交进仓库**（`data/` 在 .gitignore 里，测试不能依赖它）。提取脚本放 `tools/`，可重跑。样本必须**原样保留**这几个真实形态：`offset` 相差三个数量级、`times[sid].t` 有 null、`gaps` 里只有 `before` 的和两端都没有的、`status` 全是 `draft`（那两本书的线都没被作者确认过，所以 fixture **覆盖不到 `confirmed`**，要测得自己改副本）、`outlines` 为空数组。
  - 不自己凭空捏数据——②c 的教训是「测试自己捏的假契约，测的是自己的假设」（`canonical_map` 键写成中文那次，28 个测试全绿但真跑一条都归一不了）。
- **不做 e2e。**
- **关键页面人工截图核对**：测试和 typecheck 抓不到任何画面硬伤。每个页面第一次做完要在浏览器里看真实渲染。

## 10. 跟总 spec 的偏差

| 总 spec | 本文 | 原因 |
|---|---|---|
| 第 8 章 11 个页面平铺 | 9 个一期页面，其中实体确认/归线确认做成流水线的子路由 | 这两页只在第 5、6 步有用，不占永久导航位（第 3 章） |
| 第 8 章 流水线页显示「累计费用估算」 | 不显示费用 | 估价反复失准，作者拍板去掉（第 7.3 节） |
| 第 9 章 「估算累计费用，显示在流水线页」 | 同上，设置页单价字段一并去掉 | 同上 |
| 原型全景图：等比例时间轴 | 自动断轴 | 真数据主线只占 1.6%（第 4.2 节） |
| 原型全景图：缺口画成区间条带 | 标记点 + 两层聚合 | 真数据一半缺口没有起点，77% 的区间只有 3 像素（第 4.4 节） |
| 原型全景图：三种条带（正文/提纲碎片/大纲提到没写） | 只画正文；缺口用标记点 | `outlines` 在两本真书里全是空的（第 4.3 节） |
