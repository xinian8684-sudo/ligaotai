## 2. 前置改造：场景卡的 `facts`（步骤 4）

### 2.1 为什么要改

拿 ②b 验收的真场景卡实测，现在的 `facts` 撑不起「按 (主语, 属性) 分组」：

| | 雪月梅传 | 西游记 |
|---|---|---|
| 场景卡 | 133 张 | 268 张 |
| `facts` 条数 | 1538 | 2893 |
| **不同属性名** | **991 种** | **1612 种** |
| (主语,属性) 分组 | 1408 组 | 2478 组 |
| 值不一致的组 | 83 | 180 |

三个病，根子都在 `prompts/cards.md` 对 `attribute` 一个字的约束都没有：

1. **属性名碎片化**：平均每种属性只出现 1.6 次，绝大多数组只有一个值，进不了比对。
2. **繁简各写一份**：`年齡`/`年龄`、`行動`/`行动`、`變化`/`变化`、`法術`/`法术` 各自成组，天然比不上。
3. **一大半不是设定，是流水账**：出现最多的属性是「行動」「言語」「心事」「反應」。同一个人每场做不同的事不叫矛盾。筛出来的 180 组里几乎全是 `行者·行動` 这类噪声，唯一像样的 `岑秀·官職 → [中書, 位卑, 內閣中書, 御史]` 还是随剧情升官的合理变化。

`书库/` 目前是空的，作者真稿还没跑过场景卡，所以改提示词**没有重跑真稿的成本**，只需重跑两本验收书。

### 2.2 受控属性表

写进 `prompts/cards.md`，也在代码里留一份常量（`src/ligaotai/facts.py` 的 `ATTRS`），两边必须一致，由测试守住。

| 组 | 属性 |
|---|---|
| 人物·身世 | 年龄、性别、外貌、籍贯、出身、亲属、师承 |
| 人物·社会 | 身份、官职、称号、别名、所属、居所 |
| 人物·能力 | 性格、本领、兵器、坐骑 |
| 人物·状态 | 伤病、生死 |
| 地点/组织/物件 | 位置、归属、规模、来历、形制 |
| 兜底 | 其他 |

共 24 个受控值 + 「其他」。

### 2.3 提示词要加的硬约束

1. `attribute` **只能**从上表里挑一个，一律写简体；实在挑不出的写「其他」。
2. `facts` 只记**跨场景稳定的设定**——换个场景还成立的那种。一次性的动作、这一场说的话、当下的心情、这一仗的战况**不准进 facts**，它们进已有的 `events` 字段。
3. `value` 是**短值**，不超过 15 个字，写那个设定本身（「如意金箍棒」「十六岁」「青州」），不要写成一句叙述。
4. `subject` 照旧照原文写法抄（归一化在步骤 7 做），但 `attribute` 和 `value` 写简体。
5. 其余照旧：`quote` 必须是片段里一段连续原文、不许省略号拼接、去标点后至少 4 个字。

### 2.4 校验

`cards.py` 的 `check_card` / `clean_card` 加：

- `attribute` 不在受控表里 → 归到「其他」，记进 `dropped`（不当失败，不重试，避免为这种小事多花 3 次调用）。
- `value` 超过 15 字 → 记进 `dropped` 并丢掉这条 fact（长值说明模型又在写流水账）。
- 这两项的计数写进 `book.json` 步骤 `cards` 的 summary，跑完能看出模型听话程度。

改完重跑两本验收书的场景卡，作为 2.1 那张表的对照，写进验收记录。

## 3. 步骤 7 总览

```
                ┌─ 支线档案（每条线 1 次调用）──┐
世界与支线.json ─┼─ 世界设定集（每个世界 1 次）─┼─→ 全书地图（1 次调用）
+ 场景卡         └─ 矛盾扫描（程序分组 + 按批）─┘
```

- 前三件互不依赖，并行跑。三件都完成后，程序先做一次**回填**（把世界设定集里的「（多个说法）」补上对应的 `C-` 编号，见第 5 节，不花钱），再跑全书地图——地图读的是档案正文，不读场景卡，也要引用 `C-` 编号。
- 提示词一件一个文件：`prompts/archive_thread.md`、`archive_world.md`、`contradictions.md`、`map.md`。
- 缓存、暂停、`FatalLLMError`、重试次数：全部沿用 ②b 第 2.6 节的共同规则，缓存文件 `档案缓存.json`。

### 3.1 引用格式（四件东西共同的硬规则）

档案和地图里**每一句结论都要带场景编号**，格式固定 `[S-0003]`，多个写 `[S-0003,S-0120]`。这是验收「编造率」的基础，脚本用正则 `\[S-\d{4}(?:,S-\d{4})*\]` 抓。

提示词里明确：拿不出编号的话就别写这句。

## 4. 支线档案（每条线 1 次调用）

**输入**：这条线的场景卡（按 `世界与支线.json` 里的线内顺序，每张压成一行：编号 + summary + 规范化人物 + 地点 + 故事时间）、这条线的 `end`（断点）、这条线名下的 `gaps`、以及线内所有 `hooks_planted` / `hooks_resolved`。

**输出** `档案/支线/L-001.md`，固定小节：

```markdown
# L-001 <线名>
- 所属世界：W-01
- 一句话：<这条线讲什么>

## 来龙去脉
<按线内顺序讲清楚，每句带编号>

## 主要人物
- <规范名>：<在这条线里是什么角色、做了什么> [S-0003]

## 写到哪
- 状态：完结 / 待定
- 最后一块：[S-0120]
- 断点说明：<从 end.note 来>

## 缺口
- <事件文本>：提到于 [S-0150]，位置大约在 [S-0004] 和 [S-0120] 之间

## 开放的伏笔
- <伏笔>：埋于 [S-0030]，至今没回收
```

- 「开放的伏笔」由程序先算（这条线里出现在 `hooks_planted`、但全书 `hooks_resolved` 里没有语义相近项的），再交模型润色成句。**先程序后模型**，避免模型漏。
- 缺口**按内容认，不写 `Q-` 编号**（`Q-` 每次重跑会重排，已知问题里那条待办）。

## 5. 世界设定集（每个世界 1 次调用）

**输入**：这个世界下所有场景卡的 `facts`（已按第 6 节的①②做过归一：规范主语 + 受控属性 + 短值 + 编号），加上世界的 `reason`（判定依据）和这个世界下的设定笔记块（`notes`）原文。

跟矛盾扫描不同，设定集**包含落在「其他」的 facts**——它是给人看的资料，不是用来比对的，宁可全一点。

**输出** `档案/世界/W-01.md`：世界名与判定依据 → 按受控属性表的分组分节列设定条目，每条带编号 → 这个世界下有哪几条线（列编号和线名）。

同一 (主语, 属性) 有多个值时，设定集里**并列列出**，不由这一步替作者选。设定集和矛盾扫描是并行跑的，写档案时 `C-` 编号还不存在，所以提示词里让模型在这种条目末尾固定写 `（多个说法）`；**矛盾扫描跑完后由程序回填**成 `（多个说法，见矛盾 C-007）`，按 (规范主语, 属性) 对上。回填是纯文本替换，不再花钱。

## 6. 矛盾扫描

### 6.1 管线

**① 主语归一**：用 `实体.json` 的规范名映射把 `subject` 换成规范名（人物、地点、组织三类都映）。映不上的保持原样，单独成组，不硬凑。

**② 属性归一**：繁转简（`opencc` 或内置映射表，跟已有依赖对齐），再对到受控表。落「其他」的**不参与分组**（它们本来就是模型没想清楚的东西，送去比对只会制造误报）。

**③ 分组**：按 (规范主语, 受控属性) 分组，组内值去重。

**④ 程序先合并明显同义的值**（降本，减少送模型的组数）：
- 完全相同 → 合并；
- 一个值是另一个的**连续子串**（「金箍棒」⊂「如意金箍棒」）→ 合并到长的那个，保留两处引用；
- 数字规范化后相同（「十六」/「16」/「十六岁」）→ 合并。

合并后值仍 ≥2 种的组，才进候选。

**⑤ 按批送模型**：每批若干组（按输入 token 上限切，配置项 `contradictions_batch_tokens`，默认 3 万）。每组给：规范主语、属性、各个值 + 每个值的 `quote` + 场景编号 + 该场景的**全局故事时间**（`thread.offset + times[sid].t`，带 `conf`）+ 所属线编号。

时间只作**参考**给模型判断「是不是随故事推进的合理变化」，**不拿它做硬判断**——②b 已证实时间估计不硬。`conf` 低的在输入里明确标出来。

**⑥ 模型只答四件事**（`response_format: json_object`，pydantic 校验）：
- `status`：`真矛盾` / `合理变化` / `无法判断`
- `level`：`严重` / `中等` / `轻微`（`合理变化` 时留空）
- `category`：`人物` / `设定` / `时间` / `称谓`
- `reason`：一句话理由，**必须带场景编号**

**宁可多报**（作者定的）：模型拿不准一律给 `无法判断` 而不是 `合理变化`，`无法判断` 在界面上跟 `真矛盾` 一起显示。

**⑦ 落盘**：见 7.2。界面（计划③）默认只展开 `level=严重` 的。

### 6.2 规模控制

按 2.1 的实测，改完提示词后估计每本书候选组在几十到几百量级，一次全书调用数在个位数批次。如果候选组超过配置上限（`contradictions_max_groups`，默认 2000），按 (值的种类数 × 涉及场景数) 排序取前 N，其余记进 `矛盾.json` 的 `skipped` 并在 summary 里报出来，不静默丢弃。

## 7. 数据文件

### 7.1 `档案/index.json`（对账与过期）

```json
{
  "threads": {
    "L-001": {"file": "档案/支线/L-001.md", "sig": "<输入签名>", "scenes": ["S-0003"],
              "world": "W-01", "outdated": false, "generated": "2026-09-16T10:00:00+08:00"}
  },
  "worlds": {"W-01": {"file": "档案/世界/W-01.md", "sig": "…", "outdated": false, "generated": "…"}},
  "map": {"file": "全书地图.md", "sig": "…", "outdated": false, "generated": "…"}
}
```

- **输入签名** `sig`：支线档案 = 这条线的（线名 + 有序场景编号列表 + 每块的 `scene_hash` + 该线的 `end`/`gaps`）的哈希；世界设定集 = （世界名 + 该世界所有块的 `scene_hash` + 规范名映射版本）的哈希；地图 = 全部档案文件内容的哈希。
- **按编号对账**（已知问题里那条待办）：`index.json` 里有、但 `世界与支线.json` 里已经找不到对应线/世界的档案，标 `outdated: true` 并在 summary 里列出来，**不自动删文件**（作者可能还想看）。

### 7.2 `矛盾.json`

```json
{
  "generated": "2026-09-16T10:00:00+08:00",
  "next_id": 8,
  "groups": [
    {
      "id": "C-007",
      "subject": "孙悟空", "attribute": "兵器",
      "status": "真矛盾", "level": "严重", "category": "人物",
      "reason": "两处都在取经途中，同一件兵器写成了两个名字 [S-0014][S-0207]",
      "values": [
        {"value": "如意金箍棒",
         "scenes": [{"id": "S-0014", "quote": "…", "thread": "L-001", "t": 3.0, "conf": "高"}]},
        {"value": "降妖宝杖",
         "scenes": [{"id": "S-0207", "quote": "…", "thread": "L-001", "t": 5.0, "conf": "低"}]}
      ],
      "verdict": null
    }
  ],
  "skipped": [{"subject": "…", "attribute": "…", "reason": "超过上限"}],
  "stats": {"facts": 1538, "grouped": 1408, "dropped_other": 210,
            "candidates": 83, "merged_by_program": 24, "sent": 59,
            "真矛盾": 12, "合理变化": 40, "无法判断": 7}
}
```

- `id` 取文件顶层只增不减的 `next_id`（沿用②a/②b 编号教训）。同一 (规范主语, 属性) 重跑后沿用原编号。
- `verdict` 留空，二期作者裁决写这里。

### 7.3 `全书地图.md`（L3，约 2 万字）

全书概况 → 每个世界一节（世界设定摘要 + 该世界下各条线一段摘要 + 交汇点）→ 严重矛盾清单（引用 `C-` 编号）→ 缺口总览 → 全书断点（哪些线没写完）。

输入是全部档案 md 的正文（不是场景卡），所以它能装得下。

## 8. 重跑与过期

- **上游改了**：`世界与支线.json` 一变，只有**受影响的线/世界**的档案标过期（`sig` 对不上），没动的线不重跑。场景卡变了、实体规范名映射变了，同理按 `sig` 判。
- **地图**：任何一份档案重跑了，地图就过期。
- **矛盾**：`facts` 或规范名映射变了就整体重跑（它本来就是全书一把算的）；已有的 `verdict` 按 (规范主语, 属性) 迁移到新组上，迁不上的记进 `矛盾.json` 的 `orphan_verdicts`。
- **跑的途中上游变了**：沿用 ②b 第 5 节的做法，开跑和跑完各算一次输入指纹，不一致这一步记 `outdated` 不记 `done`。
- 单独重跑一条线/一个世界的档案：后端接口 `POST /books/{id}/archive/rerun`，参数 `{"threads": ["L-001"], "worlds": [], "map": true}`。

## 9. 验收

### 9.1 植入矛盾抄召回率

`tools/scramble.py` 加第四种弄乱方式 `--contradictions N`（默认 0，②b 的乱稿重跑时不受影响）：

1. 在已经切好的场景文本里找**锚点**：`年方X` / `X岁` 这类年龄写法、兵器词表里的词、`左/右 + 身体部位`、`颜色 + 衣/袍`、地名（从答案文件里已有的实体取）。
2. 随机挑 N 个**不同场景**，各改一处，把锚点替换成同类但不同的值（十六→二十、金箍棒→降妖宝杖、左臂→右臂）。
3. 答案文件加 `contradictions: [{"scene": "S-0014", "subject": "…", "attribute": "兵器", "old": "…", "new": "…"}]`。

**召回判据**：植入点的场景编号，出现在某个 `status ∈ {真矛盾, 无法判断}` 的组的 `scenes` 里，且该组 `attribute` 等于植入的属性 → 算召回。门槛 **≥ 8/10**。

同时报**误报数**（`status=真矛盾` 但不在植入点里的组数）——作者定了「宁可多报」，所以误报只报数不设门槛，供人工翻。

### 9.2 引用核对抄编造率

`tools/eval_archives.py`（新建）：

1. 正则抓出档案和地图里所有 `[S-xxxx]`。
2. 逐条核：**编号存在**（`场景/` 下有这个文件）、**归属正确**（支线档案里的编号必须属于这条线，世界设定集里的必须属于这个世界）。
3. 报编造率 = 不合格引用数 / 总引用数。门槛 **≤ 2%**。
4. 另报「无引用句率」：档案正文里不带任何编号的结论句占比，门槛 **≤ 10%**。

### 9.3 人工抽查

从两本书的档案里随机抽 10 段（脚本抽，写成对照文件：结论句 + 它引用的场景原文），作者人工判对错，结果记进验收记录。

### 9.4 费用

先跑 `--estimate` 估一遍再真跑，两个数都记进验收记录。**②b 的教训**：这类步骤输出 token 可能比输入还多，估算容易偏低，估的时候按输出/输入 ≥ 1 算。

验收记录写 `docs/验收记录/2026-09-16-计划2c-档案矛盾地图.md`。

- 集成：假模型跑通四件东西，验证并行调度、缓存命中、暂停取消、单独重跑一条线不动别的线。

## 11. 跟总 spec 的偏差

| 总 spec | 本文 | 原因 |
|---|---|---|
| `facts.attribute` 自由填 | 受控属性表 24 项 + 其他，`value` ≤15 字 | 实测 1612 种属性名，分组失效（第 2 节） |
| 步骤 7 含「故事时间线冲突检查」 | 不做，记进待办 | 时间估计本身不硬（②b L-003 τ=0.32） |
| 矛盾扫描直接把不一致的组交模型 | 先程序合并同义值再送 | 降本，减少误报 |
