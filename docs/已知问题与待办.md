## 计划④（二期·取舍）之后留下的

- **程序化影响第 3 项（别处引用）只用独有人物的叫法匹配，漏报在所难免**：`impact.program_impact` 只拿「只在这条线出场、且角色是主要/次要」的人物叫法，去匹配别的线场景卡的 `refs_elsewhere`。这是 spec 细化时的有意选择——拿全部人物匹配的话，主角在所有线都出现，会把每条引用都报上来，等于没报；但代价是：真正的跨线引用如果没提到这些「独有人物」的名字（比如只提到地点、事件、非独有的次要人物），就不会被列出来。界面上不能把这一项当成「保证找全」的清单。
- **骨架编辑只有上下移、没有拖拽**：spec 7.3 写的是「拖动章节顺序、在章之间移动场景」，实际做的是按钮式的「章上移 / 章下移」「移到上一章 / 移到下一章」（`SkeletonPage.vue`），没有真正的拖拽交互。
- **导出不做 docx / EPUB**（spec 范围外）：`export.py` 只支持 md 和 txt 两种格式（spec 7.4）。
- **跨线穿插顺序不准（根子在 ②b 各线时间对齐）**：9-26 真书验收（雪月梅，全留）导出顺序全局 τ=0.836，拆开看线内 0.985、跨线只有 0.779。骨架按 `offset + times[sid].t` 排，排序本身没错；错在各条线估出来的时间互相对不上：L-003 原书第 6～15 回估到 0.85 年、第 45 回只到 1.1～1.5 年，而主线同期已过 5 年（这两块单独拖掉约 0.04）。反事实：同一年内的块用原书顺序（神谕）排，τ 也只有 0.90；时间格越细 τ 越低（0.5 年 0.87、0.1 年 0.85），说明一年以内各线时间本身就互相矛盾。所以判据 2 改成只判线内 τ，跨线 τ 只报不判（`tools/eval_skeleton.passes`）。要修得回 ②b 做跨线时间校准（比如拿交汇点当锚点对齐各线时间尺度），要重跑并花钱，等作者说做。在那之前，作者在骨架页看到的线间先后只能当草稿。

## ②c 真跑之后留下的（做 ③ 之前顺手处理）

- 🔴 **植入的两个年龄值要跟时间方向反着来**（9-21 第二轮真跑发现）：`plant_contradictions` 现在随机挑两个差 ≥4 岁的值，不管哪个章节在前。雪月梅时间跨度好几年，前面的章节写 16 岁、后面写 24 岁，模型判成「合理变化」是**对的**（`C-078 鄭璞/年龄` 的理由原文：「郑璞十六岁进学与后年方二十四并不矛盾，是不同时间」），这一处就白植了。小梅那条判成真矛盾的理由里「时间与年龄增长不匹配且**倒退**」说明模型是认时间方向的。改法：`chapters[0] < chapters[1]` 时让 `ages[0] > ages[1]`，造成真正的年龄倒退；或者把差距拉大到远超全书时间跨度。改完要重新生成乱稿、重跑步骤 1–6（约 $1.5），确认过再动。
- **facts 抽取会漏掉插进去的直白陈述**（9-21 第二轮）：20 句同一句式的「X年方N歲」插进乱稿，19 句被抽成了同主语的年龄 fact，漏了小梅 ch4 那一句（值「二十八」在本章 facts 里一次都没出现）。抽取率 95% 看着不低，但漏掉的那一句正好让一处植入作废——**召回 8/10 里有 1 分是扣在抽取头上的，不是矛盾扫描**。
- **L-002 归线 τ=0.7143**（9-21 第二轮）：5 条线里全场最低，只有 8 个场景（「小梅身世与何家因果」）。加权后不影响总分过线，但它是唯一明显偏低的一条，下次单独看看是线划错了还是排序错了。
- **世界设定集有「（多个说法）」没回填 C- 编号**（9-21 两轮都有）：第一轮 9 处、第二轮 5 处（`run_archive` 返回的 `unfilled_multi`）。模型标了多说法但 `backfill()` 没找到对应的矛盾组。不影响任何门槛，但作者打开设定集会看见这个半成品标记。
- **`eval_archives.py --folder` 只认文件夹名，传路径会被硬拒**（9-21）：`--folder data/乱稿-雪月梅-c` 报「一个场景都没对上」（I3 那条修复起了作用，硬报错不静默出错数），得传 `--folder 乱稿-雪月梅-c`。帮助文本写的是「乱稿文件夹名」，但踩的人第一反应还是传路径。改法：`--folder` 收到带分隔符的值时自动取 `Path(x).name`，或者报错里直接把正确写法印出来。
- **API key 失效表现为第一次调用就 401**（9-21 实际撞到）：9-16 还能用的 key 到 9-21 失效，报 `FatalLLMError: 接口拒绝了请求（401）`。0 次调用、没花钱，书已经建好，换 key 重跑即可接上。key 在 `config.json` 的 `api_key`，也可以用环境变量 `LIGAOTAI_API_KEY`（但 config 里有值会优先）。
- **换模型不会让档案自动过期**（I2，F+DE 合并审查，9-20 定）：`archive.py` 的 `input_sig` 只哈希渲染好的模型输入文本 + 提示词内容，**不含**模型档位配置（`cache_config(client, "synth")`）——换一次模型不会让已有档案 / 矛盾扫描 / 地图判过期重跑。这是有意的（换模型 = 全部档案重付一次钱，不值），不是漏签名。已做的兜底：每份档案 / `矛盾.json` / 全书地图落盘时，`index[...]["model"]` 记下生成它用的模型名。Task 18（`docs/superpowers/plans/2026-09-16-ligaotai-plan2c-archives.md` 的 Task 18 一节）接 API 时要把这个字段吐给界面，界面对比 index 里的 `model` 和当前配置的 `synth.model`，不一样就提示作者「这份档案是用 X 模型生成的，当前配置是 Y，要不要重跑」。
- **`generation_scopes()` 吞掉异常后静默退回严格范围**（GHIJ 审查 Minor，9-20）：`tools/eval_archives.py` 的 `generation_scopes()` 捕获 `(OSError, ValueError, KeyError, TypeError)` 后返回空字典，调用方退回严格范围核对。真跑时如果 `prepare_inputs` 因为任何原因失败，编造率会无声跳高，报告里看不出原因是「真编造」还是「宽范围算不出来」。改法：报告里加一个 `lenient_available: true/false` 字段，`main()` 打印时带上。这次没改代码，下次改 `check_refs`/`estimate` 这块时一起做。

## 已知局限（暂不处理）

- **验收脚本 `estimate()`：全书地图的输入字符数是上界近似**（GHIJ 审查 Minor，9-20）：`map_chars = thread_chars + world_chars`，但真实的地图输入是**生成好的档案正文**（受 `synth.max_tokens=32768` 封顶），估算时档案还没生成，只能拿支线 + 世界的输入字符数近似。分项表里 `全书地图` 这一项的 `input_chars` 因此会比真实值大，读报告时要知道这是上界，不是准确值。
- **验收脚本：世界设定集对单世界的书没有区分力**（GHIJ 审查 Minor，9-20）：`check_refs` 的 `allowed` 并上生成时的 `world_scope` 之后，对只有 1 个世界的书（比如西游记），世界设定集的合法范围约等于全书场景，「归属正确」这项检查退化成「编号存在」。这是单世界书的固有局限，验收记录里要写明「这一项没有区分力」，别拿它当归属核对通过的证据。
- **导入**：Windows 上只改大小写的重命名（`a.txt` → `A.txt`）会被当成新文件，旧条目留着。和「源文件删了不从书里删」属于同一类。
- **查重**：同一小段文字有两份彼此相似的副本，又分别完整出现在两个不相干的章节里时，这四块仍会串成一组。需要凑巧的条件比较多。
- **切场景**：只有标题的块往后合并时，中间的分隔符行（`***`）会被包进块里。只影响显示，不丢内容。
- **场景**：`原稿/` 里的副本被手动删掉后，切场景会失败（报错带路径）。重新导入一次就会补回来。
- **验收脚本**：查重验收报告里没带导入失败 / 跳过的文件清单。
- **建书**：书名恰好是 Windows 保留名（`NUL`、`CON` 等）时，会报系统错误而不是友好提示。
- **实体合并**：`_context` 在名字与原文只差标点/全角时取不到上下文；同名跨类型（同一叫法既是人物又是地点）没处理；新出现的叫法即使实际指向某个已确认组，也不会自动并进去，会单独成 single，不提示它可能属于哪个已确认实体，要作者手动合并。
- **作者操作**：merge 每次要读全部场景卡，200 万字的书大约要 1 秒；实体文件的锁是进程内的，只支持单进程服务。
- **配置**：`PUT /api/config` 整份替换，前端必须提交完整表单；配置的读改写没加锁。
- **用量**：`add_usage` 不校验 step 名。
- **暂停**：这是设计如此——任务被暂停后步骤记为 failed，错误信息「已暂停：…」，重跑会接着做。
- **场景卡提示词**：pov 留空、quote 不许拼接两条已改（验收之后按作者意见改的，还没用真模型重跑验证，下次真跑看重试次数有没有降）；summary 要求简体但约 22% 的卡写成了繁体（未改）。
- **场景卡**（验收抽查 10 张发现，未改）：
  - 模型偶尔把名字写成简体（如「御弟師父」写成「御弟师父」），核对不做繁简转换，3 次重试后连名字带以它为 subject 的 facts 一起删掉——抽查里有一张卡因此丢了唐僧被俘经过的 4 条事实，人物名单里也没了唐僧。
  - 同一场景里同一人物换了称呼（「妖精」后面点明是「二魔」）会被列成两个人物，靠步骤 5 实体合并兜底。
  - incomplete 偶有误判：章回体「且听下回分解」的正常结尾被标成 incomplete=true，incomplete_note 自己却写着「情节并未中断」。
- **API**（代码质量审查 Minor，未改）：
  - 暂停接口对 import/split/dedup 也有效，暂停文案「做完的部分已经保存，重跑会接着做」对导入不准确（导入的清单最后才写），重跑本身没问题。
- **用量**：进程被杀（或断电）时，正在跑的这次调用不会计进 `book.json` 的用量统计（`cards.py:400-402`、`entities.py:525-527` 在 `finally` 里记账，进程被杀不会执行到）。卡和实体的缓存已经落盘，重跑不会重复花钱，只是累计费用会比实际少算一点。
- **归线**：跨线对齐、找缺口这两步的输入超过 `threads_max_input_tokens` 时直接跳过（记在 `failed_calls`），不分段。
- **归线**：模型建议归入已确认线的块（`pending`）不参与找缺口。
- **归线**：从别的线挪来的块、合并进来的线不带故事时间（不同线的线内时间对不上），要重跑步骤 6，或者作者自己排。
- **归线**：世界按名字沿用编号，模型重跑时给世界换了名字，编号就会跟着变。
- **归线**：线内排序不分段，也没有预算保护——一条三千块左右的大主线，输出会碰到上限，截断后这条线退回按原稿位置暂排。②b 验收时最大的线是 210 块，没碰到。
- **归线**：线内排序遇到「模型给的故事时间和它自己排的顺序互相矛盾」时不反馈重试，按给出的顺序算。
- **归线**：模型按片段编号（`P-…`）给时间时，这个片段里的块都拿不到时间（提示词已写明「times 按 S- 编号给」，只是缓解）。
- **归线**：跨线对齐不检查交叉的交汇点，也不检查一个支线块对上两个主线块。
- **归线**：编号匹配放宽之后（`S-1` / `S0001` 都认成 `S-0001`），模型把编号写错时，有可能被认成另一个真实存在的编号。
- **归线**：拆线时，指向被拆走的块的交汇点 / 缺口，`after`、`before` 不会改指到别的块，直接删掉或置空。
- **归线**：失败 / 没解决清单里，排空后被丢掉的线、排序时保持临时键的 tag 都只记不修。
- **归线输入**：版本组的主版本已删除、又没重跑查重时，同组其余块会进未分配，原因写「版本组的主版本已删除，要重跑查重」。只有直接调 `run_threads` / `prepare` 才碰得到，走接口不会。
- **API**：线元素级的脏数据（比如某条线少了 `outlines` 键）会让 KeyError 映射成 404「没有这条线或这个世界」，提示误导。同「手改文件」那一类。
- **作者操作**：归线文件的锁也是进程内的，只支持单进程服务（同实体合并）。
- **验收脚本**：`eval_threads.py --estimate` 把「实体合并已完成」算成 0 元（实际缓存没命中会重算）；片段副本成了主版本时标准位置会算错；原稿清单核对失败时不写 `-error` 报告。
- **归线排序**（②b 验收实测，未改）：跨度大、时间锚点弱的支线，模型会按线名字面上的因果顺序排，而不是按文本里的时间线索。《雪月梅传》的 L-003「刘电蒋士奇搬柩结姻」18 块横跨第 15–49 回，模型把「搬柩寻访」（第 21、38–41 回）当成开头、把「到蒋府结姻」（第 15、16 回）当成后续，恰好和原书相反，单线 τ 只有 0.32（整本加权 τ 仍是 0.93）。这条线模型给的 `conf` 大多是「中 / 低」——界面上要能按 `conf` 把这种段落标出来让作者复核。
- **缺口**（②b 验收实测，未改）：缺口抓的是对话里回指的往事，不是「整回内容缺失」。后文常复述前情的稿子（《西游记》）效果很好，删掉的 5 回 5 条全被标出来、每条都给了位置；后文不复述的稿子（《雪月梅传》）删掉的 5 回一条都没标出来，91 条缺口里 87 条连 `after`/`before` 都是空的。**缺口不能当查漏工具用**，界面上别这么介绍它。
